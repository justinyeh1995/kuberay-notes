API Codegen Workflow

整理自 2026-11-02 的問答 · 對照 KubeRay repo 驗證 · 相關筆記:CRD Installation · Operator RBAC

一句話:改了 ray-operator/apis/ray/v1/*_types.go,就跑 make generate + make sync(最精簡是 make generate helm)。

  • make sync 不產生 DeepCopy;make generate 不同步 Helm CRD。兩個都要。
  • Helm chart 裡的 RBAC template 沒有任何 make target 會產生,要手動跟 config/rbac 對齊。

1. Makefile target 各做什麼

ray-operator/Makefile

manifests: controller-gen
	$(CONTROLLER_GEN) $(CRD_OPTIONS) rbac:roleName=kuberay-operator webhook paths="./..." output:crd:artifacts:config=config/crd/bases

generate: manifests api-docs controller-gen
	$(CONTROLLER_GEN) object:headerFile="hack/boilerplate.go.txt" paths="./..."
	./hack/update-codegen.sh

helm: manifests
	rm -r ../helm-chart/kuberay-operator/crds/
	cp -r config/crd/bases/ ../helm-chart/kuberay-operator/crds/

sync: helm api-docs
	./hack/update-codegen.sh

ApplyConfig		api-docsHelm CRD

make generate✓✓✓✓✗

  • manifests:controller-gen 讀 kubebuilder marker,產生 config/crd/bases/*.yaml、config/rbac、webhook 設定。make deploy 和 envtest 讀這裡。
  • helm:把 config/crd/bases/ 整份複製到 helm-chart/kuberay-operator/crds/,helm install 讀這裡。漏跑的話 Helm 使用者送的新欄位會被 apiserver pruning 掉。
  • api-docs:crd-ref-docs 產生 docs/reference/api.md。
  • hack/update-codegen.sh:k8s code-generator,產生 pkg/client 底下的 clientset、informer、lister、ApplyConfiguration。

ray-operator/DEVELOPMENT.md 的 Consistency check 一節只寫 make sync,沒提 DeepCopy。新增 struct 或 pointer 欄位時,zz_generated.deepcopy.go 只有 make generate 會更新。

2. CI 檢查什麼

.github/workflows/consistency-check.yaml:

  • hack/verify-codegen.sh、hack/verify-generated-files.sh:pkg/client 與 generated files
  • hack/verify-api-docs.sh:docs/reference/api.md
  • 跑 make manifests 後看有沒有 diff:失敗訊息「Please run "make manifests" to synchronize CRD and RBAC!」
  • 比對兩份 CRD:失敗訊息「Please run "make sync" to synchronize CRDs!」
  • scripts/rbac-check.py:kubebuilder marker 與 config/rbac

哪些要手動同步?

DEVELOPMENT.md 第 6、7 點:

  • helm-chart/kuberay-operator/templates 的 RBAC 要手動跟 config/rbac 對齊。
  • multiple_namespaces_role.yaml / multiple_namespaces_rolebinding.yaml 要跟 role.yaml / rolebinding.yaml 對齊(差別只在 namespaced vs cluster-scoped)。

例:WAS PriorityClass PR 新增的 templates/priorityclass_role.yaml 就屬於這類,make 不會幫你檢查。

3. DeepCopy:完整複製,不共用底層資料

Go 的 struct 賦值是淺拷貝,裡面的 pointer、slice、map 仍指向同一份資料:

b := a              // a.Spec.WorkerGroupSpecs 這個 slice 兩邊共用
b.Spec.WorkerGroupSpecs[0].Replicas = ptr(5)   // a 也被改到

controller-gen 產生的 zz_generated.deepcopy.go 為每個型別加上 DeepCopy()、DeepCopyInto()、DeepCopyObject()。

  • runtime.Object 介面要求:所有 API 物件都要有 DeepCopyObject() 才能註冊進 scheme。新增欄位卻沒重新產生,通常還能編譯,但複製時會安靜地漏掉新欄位;新增頂層型別則會編譯失敗。
  • 不能直接改 informer cache 的物件:cache 裡的物件被所有 reconcile 共用,要改先 DeepCopy。
  • 保留修改前的版本以便比對:

ray-operator/controllers/ray/rayservice_controller.go:119

originalRayServiceInstance := rayServiceInstance.DeepCopy()

reconcile 過程改 rayServiceInstance,最後跟 original 比較,有變化才更新 status。若是淺拷貝,original 會一起被改,永遠判斷成「沒變」。

4. clientset:有型別的 Ray CR client

hack/update-codegen.sh 產生 pkg/client/clientset,用法跟 client-go 的 kubernetes.Clientset 一樣:

cs.RayV1().RayClusters("default").Get(ctx, "my-cluster", metav1.GetOptions{})
cs.RayV1().RayJobs(ns).Create(ctx, job, metav1.CreateOptions{})

同一套產生器也產生 informer、lister(pkg/client/informers/...)。

operator 自己用嗎?

不太用。operator 用 controller-runtime 的通用 client.Client。真正的使用者是:

  • kubectl-plugin(kubectl ray create / job / scale)
  • apiserver、apiserversdk
  • 外部使用者自己寫的 Go 程式
  • operator 的 unit test 用它的 scheme 套件註冊 Ray 型別(例:rayjob_controller_unit_test.go:34)

5. ApplyConfiguration:Server-Side Apply 用的 builder

問題:Server-Side Apply(SSA)的語意是「只宣告我在乎的欄位」,apiserver 用 managedFields 記錄每個欄位由誰管理。直接序列化 rayv1.RayCluster struct,沒填的欄位會變成零值(0、""、false)送出,apiserver 分不出「我要設成 0」還是「我不管」,結果搶走別人管理的欄位。

解法:ApplyConfiguration 的欄位全是 pointer,搭配 WithXxx() builder,沒呼叫到的就是 nil,不會送出:

ray-operator/test/e2erayjob/rayjob_recovery_test.go:31

rayJobAC := rayv1ac.RayJob("counter", namespace.Name).
    WithSpec(rayv1ac.RayJobSpec().
        WithRayClusterSpec(...))

cs.RayV1().RayJobs(ns).Apply(ctx, rayJobAC, metav1.ApplyOptions{FieldManager: "e2e"})

KubeRay 裡主要用在 e2e test(ray-operator/test/...),以及給想用 SSA 的外部使用者。
