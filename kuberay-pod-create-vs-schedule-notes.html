Kubernetes 基礎 · 延伸自 issue #5364

Pod Create vs Schedule

整理自 2026-10-05 的問答 · 相關筆記:Worker Group Deadlock Notes

一句話:「建立 Pod」和「把 Pod 排到 node 上」是兩個分開的步驟,由不同元件負責、發生在不同時間點。r.Create 只參與第一步。

  • ResourceQuota 在建立之前由 apiserver 檢查,超額直接回 403,Pod 不會被存起來。
  • node 資源不夠在建立之後由 kube-scheduler 發現,r.Create 早就拿到 201,Pod 只是卡在 Pending。
  • 所以只有前者會讓 createWorkerPod 收到錯誤,觸發 #5364 的卡死。

1. 為什麼 node 不夠時,createWorkerPod 不會收到錯誤?

Pod 卡在 Pending,createWorkerPod 不會收到錯誤,為什麼?

r.Create 是對 apiserver 發一個 HTTP 請求,意思是「幫我把這個 Pod 物件存起來」。apiserver 檢查完、寫進 etcd,就回 201 Created。在這個時間點,沒有人檢查過哪個 node 有空間。

建 Pod 的兩個階段

階段一 · 建立(同步)

KubeRay → apiserver

  1. 認證、授權
  2. admission(含 ResourceQuota)
  3. 驗證 Pod spec
  4. 寫進 etcd
成功 → 回 201 Created,Pod 存在了,phase: Pending
quota 超額 → 回 403 Forbidden,Pod 不存在

階段二 · 排程(非同步)

kube-scheduler → kubelet

  1. watch 到沒排程的 Pod
  2. 找有足夠資源的 node(用量、taint、affinity…)
  3. 找到就 bind 到 node,kubelet 啟動 container
找到 → Pod 變成 Running
找不到 → 標記 Unschedulable,Pod 繼續 Pending
KubeRay 在階段一拿到 201 就結束了,階段二的結果不會回傳給它

2. 兩種「資源不夠」發生在不同的步驟

在哪個步驟檢查誰檢查r.Create 收到什麼
ResourceQuota階段一,建立之前apiserver 的 admission403 Forbidden,Pod 不會被存起來
node 資源不夠階段二,建立之後、非同步kube-scheduler201 Created,Pod 已存在,只是排不上去

ResourceQuota 問的是「這個 namespace 有沒有權利再多一個 Pod」,只要算加總,apiserver 馬上就能判斷,所以在建立時直接拒絕。

node 資源問的是「哪台機器放得下」,要看每台 node 的用量、taint、affinity,這是 scheduler 的工作。scheduler 在 Pod 已經存在之後才看到它,就算找不到 node,也只是在 Pod 的 status 寫上:

status:
  phase: Pending
  conditions:
  - type: PodScheduled
    status: "False"
    reason: Unschedulable
    message: "0/3 nodes are available: 3 Insufficient cpu."

這個結果不會回傳給 KubeRay,r.Create 早就拿到 201 結束了。

3. 對 KubeRay reconcile 迴圈的影響

情況createWorkerPod迴圈下一輪
node 不夠回傳 nil繼續,跑到 group BPending 的 Pod 算進 runningPods,diff 是 0,不會一直重建
quota 滿回傳錯誤L1210 return,group B 跑不到一樣的錯誤,一樣的結果(#5364)

這也是為什麼 Pending 的 Pod 能被 Cluster Autoscaler 或 Karpenter 處理:它們看到 Unschedulable 的 Pod 就去加 node。被 quota 擋下的 Pod 根本沒被建立,它們什麼也看不到。

延伸:不只 ResourceQuota,任何在階段一拒絕 Pod 的東西(policy webhook、Pod Security Admission、LimitRange、不合法的 spec)都會讓 r.Create 收到錯誤。判斷一個「資源不夠」會不會觸發 #5364,就看它發生在階段一還是階段二。
